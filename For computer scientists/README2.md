- Databases:
  + Check a functional dependency by asking for a counterexample [link](NORMALIZATION.ipynb). <details><summary>Click to expand description</summary> Whether a relation is well designed comes down to its functional dependencies: which attributes determine which others. For attributes X and Y, X determines Y if any two rows that agree on X also agree on Y. The notebook represents two arbitrary rows as dictionaries of Z3 string variables, encodes that implication as a constraint, and then checks a dependency by asking the solver for two rows that agree on X but differ on Y. When the solver answers "unsat" there is no counterexample, so the dependency holds. <br><br> <b>Student task:</b> write the body of the function that encodes a functional dependency, and write the counterexample constraint used to check one. <br> <b>Z3 primer:</b> booleans.</details>

  + Determine whether a relation is in 2NF and 3NF [link](NORMALIZATION-ADVANCED.ipynb). <details><summary>Click to expand description</summary> The sequel to the notebook above. A relation is in 2NF when no non-key attribute depends on only part of the key, and in 3NF when no non-key attribute depends on another non-key attribute. Both conditions are statements about which dependencies exist, so once the solver can check one dependency it can check the whole normal form. The notebook works through a relation that fails 2NF and a second one that satisfies it. <br><br> <b>Student task:</b> complete the 2NF check by testing each non-prime attribute against each part of the key, set up the row variables and dependencies for the second relation, and complete the 3NF check. <br> <b>Z3 primer:</b> booleans.</details>

- Algorithm analysis:
  + Asymptotic bounds: show f = Omega(g). [link](ASYMPTOTIC-BOUNDS.ipynb). <details><summary>Click to expand description</summary>For functions f(n) and g(n), f = Omega(g) if it there exist constants c and n0 such that c*f(n) >= g(n) for all n >= n0. This notebook walks students through showing f = O(g) using Z3 and then tasks them with doing the same for f = Omega(g). The solver is asked for the constants themselves, and a helper plots c*g(n) overtaking f(n) at the n0 that Z3 found. <br><br> <b>Student task:</b> complete a quantified implication over a range, then write the body of the big-Omega solver. <br> <b>Z3 primer:</b> reals.</details>

  + Apply the Master Theorem using asymptotic bounds from Z3 [link](ASYMPTOTIC-BOUNDS-MASTER-THEOREM.ipynb). <details><summary>Click to expand description</summary> A longer version of the notebook above that carries the bounds through to algorithm analysis. After building the O and Omega solvers, the student writes a function that takes a, b and f from a recurrence T(n) = a T(n/b) + f(n), builds g(n) = n^(log_b a), and reports which of the three Master Theorem cases applies. It is run on merge sort, on a case-3 recurrence, and on the naive divide and conquer matrix multiplication. The notebook also shows the solver answering "unsat" on a claim that is false, and closes with a caution about recurrences where log_b a is not a whole number, which Z3 will not settle quickly. <br><br> <b>Student task:</b> complete the quantified constraints for O and Omega, write the Master Theorem function, and supply a, b and f(n) for three recurrences. <br> <b>Z3 primer:</b> reals.</details>

- Theory:
  + Find maximum matching in a bipartite graph [link](MATCHING.ipynb). <details><summary>Click to expand description</summary> A matching is a collection of edges in a graph where each edge is disjoint, i.e., shares no vertices. The objective of this notebook is to find a matching in a given bipartite graph. Employees and tasks are given as plain lists, each possible assignment becomes a boolean variable, and the constraints say that no employee takes two tasks, no task goes to two employees, and every task is covered. <br><br> <b>Student task:</b> none — this notebook is read and run rather than filled in. <br> <b>Z3 primer:</b> booleans.</details>

  + Construct a solver for k-Clique [link](CLIQUE.ipynb). <details><summary>Click to expand description</summary>For a graph G, a k-clique is a subset of vertices, S, of G such that: (1) each pair of vertices in S is adjacent, and (2) the cardinality of S is k. Given a graph G and integer k, the CLIQUE problem is to determine if a given graph has a k-clique. The objective of this notebook is to use Z3 to make a CLIQUE solver. Graphs are built with NetworkX first, and the solver is tested on a complete graph and on a 5-cycle, which has no triangle. <br><br> <b>Student task:</b> write the whole body of <code>makeCLIQUESolver(G, k)</code> — the constraint ruling out non-adjacent pairs, and the constraint forcing at least k vertices to be selected. This is the most demanding notebook in the set; it expects comfort with loops, dictionaries and <code>itertools</code>. <br> <b>Z3 primer:</b> booleans.</details>

  + Verify a sender gadget for K3K3-NONARROWING. [link](K3K3-NONARROWING.ipynb). <details><summary>Click to expand description</summary>A K3 is the complete graph on three vertices. Given a graph G, the K3K3-NONARROWING problem is to determine whether a graph has a K3K3-good coloring, where a K3K3-good coloring is a red/blue coloring of G’s edges such that there are no red K3’s and no blue K3’s. Such a coloring is called a K3K3-good coloring. This is illustrated below: <br> <img width="500" alt="K3K3-example" src="https://github.com/user-attachments/assets/86cc4f5c-14b4-4489-a484-c069d9448aa9" /> <br> K3K3-NONARROWING is an NP-complete problem that asks whether a given graph has a red/blue edge-coloring such that there are no red K3's and no blue K3's. The NP-hardness proof of this problem relies on a special graph called a K3K3-sender: a graph G with "sender edges" e and f such that e and f are distinct and e has the same color as f in all K3K3-good colorings of G. The objective of this notebook is to construct and verify the correctness of a K3K3-sender. The sender is verified twice over: once by enumerating every good coloring and checking the two edges always agree, and once by asserting that they differ and getting back "unsat". <br><br> <b>Student task:</b> build the sender graph in NetworkX, add the clauses forbidding monochromatic triangles, and add the clause forcing the two sender edges to differ. <br> <b>Z3 primer:</b> booleans.</details>

  + Decide whether two graphs are isomorphic [link](GRAPH-ISOMORPHISM.ipynb). <details><summary>Click to expand description</summary> Two graphs can be drawn completely differently and still be the same graph underneath, relabelled. Deciding whether that is the case is the graph isomorphism problem, and it is one of the few problems known to be neither easy nor NP-complete. The notebook uses Z3's <code>Function</code> datatype to search for a mapping from the nodes of G to the nodes of H, constrains it to be a bijection that carries every edge to an edge, and runs it on a pair of graphs that are isomorphic and a pair that are not. A helper draws the two graphs side by side with the recovered mapping. <br><br> <b>Student task:</b> none — this notebook is read and run rather than filled in. <br> <b>Z3 primer:</b> booleans and integers. <br> <i>The same notebook also appears in <a href="../For%20mathematicians/README.md">For mathematicians</a>.</i></details>

For example, a solution on an 8x8 board is shown below. The objective of the notebook is to find all solutions for the ROOKS problem on a 4x4 board. <br> <img width="377" height="375" alt="rooks" src="https://github.com/user-attachments/assets/be4e42d4-2877-474f-ae1d-f1203317d694" /> <br> The 3x3 case is worked through first, including how to block a solution the solver has already found so that the rest can be enumerated. <br><br> <b>Student task:</b> encode the row and column constraints for the 4x4 board and enumerate all 24 solutions. <br> <b>Z3 primer:</b> booleans.</details>
